# 项目规则文档

## 1. 项目概述

本项目是一个 ComfyUI 自定义节点集合，用于扩展 ComfyUI 的功能。

## 2. 目录结构

```
py-comfy-nodes/
├── __init__.py          # 包初始化文件
├── pyproject.toml       # 项目配置文件
├── README.md            # 项目说明文档
├── js/                  # JavaScript 前端代码
├── yaml_folder/         # YAML 配置文件
├── rules/               # 规则文档
└── py_*.py              # 自定义节点实现
```

## 3. 代码风格指南

### 3.1 Python 代码

- 遵循 PEP 8 编码规范
- 使用 4 个空格进行缩进
- 每行最大长度 100 字符
- 变量命名使用小写字母和下划线（snake_case）
- 类命名使用驼峰命名法（CamelCase）
- 函数和方法命名使用小写字母和下划线（snake_case）
- 常量使用全大写字母和下划线

### 3.2 JavaScript 代码

- 遵循 ESLint 标准规范
- 使用 2 个空格进行缩进
- 每行最大长度 100 字符
- 变量和函数命名使用驼峰命名法（camelCase）
- 类命名使用大驼峰命名法（PascalCase）

## 路径规范

- 所有的 js 文件都放在 js/ 目录下

## 4. 命名规范

### 4.1 文件命名

- Python 文件：`py_<功能描述>.py`，例如 `py_PromptFromFile.py`
- JavaScript 文件：使用小写字母和连字符，例如 `custom-node.js`
- YAML 文件：使用小写字母和连字符，例如 `config.yaml`

### 4.2 节点命名

- 类名：`CamelCase` 格式，例如 `PromptPyFromFile`
- 节点显示名称：使用清晰描述性的名称

## 5. 节点实现规范

### 5.1 基本结构

```python
class NodeName:
    """节点描述"""

    @classmethod
    def INPUT_TYPES(cls):
        """定义节点输入参数"""
        return {
            "required": {
                # 必填输入参数
            },
            "optional": {
                # 可选输入参数
            },
        }

    RETURN_TYPES = ("TYPE1", "TYPE2")
    RETURN_NAMES = ("output1", "output2")
    FUNCTION = "node_function"
    CATEGORY = "category"

    def node_function(self, input1, input2=""):
        """节点执行逻辑"""
        # 实现逻辑
        return (output1, output2)
```

### 5.2 输入参数

- 明确指定参数类型
- 为可选参数提供默认值
- 使用描述性的参数名称

### 5.3 输出参数

- 明确指定输出类型
- 使用描述性的输出名称
- 确保返回值与声明的类型一致

## 6. 文档规范

### 6.1 代码注释

- 为类、方法和函数添加文档字符串
- 对复杂逻辑添加行注释
- 使用中文注释，保持与项目语言一致

### 6.2 README.md

- 包含项目概述
- 列出所有节点及其功能
- 提供安装说明
- 包含使用示例

## 7. 版本控制规范

### 7.1 Git 提交消息

- 明确指定 git 提交时再执行, 生成代码时不执行
- 只提交当前项目, 不要切换到主项目
- 使用清晰、简洁的提交消息
- 提交消息格式：`<类型>: <描述>`
  - 类型：feat（新功能）、fix（修复）、docs（文档）、style（样式）、refactor（重构）、test（测试）、chore（构建/依赖）
  - 描述：简短描述更改内容

### 7.2 分支管理

- `master`：主分支，保持稳定
- `develop`：开发分支，用于集成新功能
- 特性分支：用于开发特定功能

## 8. 测试规范

- 为新功能添加测试用例
- 确保现有功能在修改后仍然正常工作
- 测试边缘情况和异常情况

## 9. 依赖管理

- 在 `pyproject.toml` 中指定依赖
- 避免使用过时的依赖
- 定期更新依赖版本

## 10. 发布规范

- 为每个版本添加版本号
- 更新 `README.md` 中的版本信息
- 提供版本更新日志

## 11. 安全规范

- 避免硬编码敏感信息
- 验证用户输入
- 处理异常情况
- 遵循安全最佳实践

## 12. 贡献指南

-  Fork 项目仓库
-  创建特性分支
-  提交更改
-  推送分支
-  提交 Pull Request

## 13. 代码审查流程

- 至少需要一名 reviewer 批准
- 检查代码风格和质量
- 验证功能是否正常
- 确保测试通过

## 14. 故障排除

- 记录常见问题和解决方案
- 提供详细的错误信息
- 维护问题跟踪系统
